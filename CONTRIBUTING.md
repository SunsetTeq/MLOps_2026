# Как вносить изменения

## Подготовка

Для работы нужны Python 3.14, Poetry и Git.

После клонирования репозитория выполни из корня проекта:

```bash
poetry install
poetry run pre-commit install
```

Первая команда устанавливает проект и зависимости из `poetry.lock`.
Вторая подключает проверки перед коммитами. Её нужно выполнить
один раз в каждой локальной копии репозитория.

Python-код находится в `src/mlops/`.

## Инструменты и стиль кода

Используем Ruff для проверки кода, сортировки импортов и форматирования.
Pre-commit запускает линтер и форматер перед коммитом.

Настройки находятся в `pyproject.toml`, список хуков —
в `.pre-commit-config.yaml`.

Принятые соглашения:

- отступы — четыре пробела;
- кавычки — двойные;
- целевая длина строки — 88 символов;
- переводы строк — LF;
- импорты сортируются автоматически.

Ruff проверяет неопределённые имена, неиспользуемые импорты,
организацию кода и потенциальные ошибки. Форматирование поддерживает
единый внешний вид файлов.

## Проверки и исправления

Проверить код без изменения файлов:

```bash
poetry run ruff check .
poetry run ruff format --check .
```

Применить доступные автоисправления и форматирование:

```bash
poetry run ruff check --fix .
poetry run ruff format .
```

Ошибки, которые Ruff не исправил автоматически, нужно исправить вручную.

Запустить все хуки на файлах под контролем Git:

```bash
poetry run pre-commit run --all-files
```

Новые файлы сначала нужно добавить через `git add`, иначе эта команда
их не проверит.

Если хук изменил файл, он может показать `Failed` и остановить коммит.
Проверь изменения через `git diff`, снова добавь исправленные файлы
в индекс и повтори проверку или коммит.

## Порядок работы

1. Переключись на `main` и получи последние изменения.
2. Создай отдельную ветку, например `dev/update-template`.
3. Внеси изменения и запусти проверки.
4. Проверь состав коммита и сохрани изменения.
5. Отправь ветку на сервер.
6. Создай Pull Request в GitHub.

В описании PR укажи, что изменилось и какие проверки выполнены.
Изменения объединяем с `main`, когда проверки проходят.

Сообщения коммитов должны объяснять изменение. Например:

- `добавил пример запуска`
- `исправил конфигурацию линтера`
- `обновил инструкцию`
- `обновил зависимости`

## Зависимости

Зависимости устанавливаем и обновляем через Poetry.

При изменении зависимостей коммитим вместе `pyproject.toml`
и `poetry.lock`. Lock-файл вручную не редактируем.

При обновлении Ruff также обновляем `rev` в
`.pre-commit-config.yaml`, чтобы ручные проверки и хуки
использовали одну версию.

Окружение `.venv/` и кеши инструментов в Git не добавляем.
