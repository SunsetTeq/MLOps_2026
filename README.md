# MLOps

Учебный шаблон Python-репозитория с настроенными инструментами
качества кода и правилами внесения изменений.

В шаблоне есть минимальный Python-пакет, зафиксированные зависимости,
линтер, форматер и проверки перед коммитом. Библиотеки для машинного
обучения не добавлены: их можно выбрать под конкретный проект.

## Стек

| Инструмент  | Назначение                                    |
| ----------- | --------------------------------------------- |
| Python 3.14 | Выполнение кода                               |
| Poetry      | Управление окружением и зависимостями         |
| Ruff        | Линтинг, сортировка импортов и форматирование |
| pre-commit  | Автоматический запуск проверок перед коммитом |

## Быстрый старт

Установи Python 3.14, Poetry и Git.

```bash
git clone https://github.com/SunsetTeq/MLOps_2026 MLOps
cd MLOps
poetry install
poetry run pre-commit install
poetry run python -m mlops.main
```

Последняя команда запускает демонстрационный модуль.

## Структура

```text
MLOps/
├── src/
│   └── mlops/
│       ├── __init__.py
│       └── main.py
├── .gitignore
├── .pre-commit-config.yaml
├── pyproject.toml
├── poetry.lock
├── CONTRIBUTING.md
└── README.md
```

`src/mlops/` содержит исходный код.
`pyproject.toml` описывает проект, зависимости и настройки Ruff.
`poetry.lock` фиксирует точные версии зависимостей.
`.pre-commit-config.yaml` задаёт проверки перед коммитом.

## Методология ведения репозитория

Используем `main` и короткоживущие ветки для отдельных задач.

В `main` хранится готовое состояние шаблона. Для изменения создаём
ветку с понятным названием, например `dev/setup-template`
или `fix/ruff-config`.

Одна ветка решает одну задачу. Изменения сохраняем небольшими
коммитами с понятными сообщениями.

Рабочий процесс:

1. Создать ветку от актуального `main`.
2. Внести изменения.
3. Запустить проверки.
4. Сделать коммиты и отправить ветку.
5. Создать Pull Request с описанием изменений и проверок.
6. После проверки объединить изменения с `main`.

Если меняются команды, зависимости или настройки инструментов,
в том же PR обновляем документацию.

Подробные команды и правила описаны в [CONTRIBUTING.md](CONTRIBUTING.md).
